---
title: Picture, sound and input
description: Black screens, silence, mouse and keyboard problems, and the Escape key.
---

Judge picture problems from a visible browser tab: a hidden tab throttles
presentation and skews every client-side number.

## Black screen, session says running

Check the session detail in **Admin ▸ Sessions**:

| Check | Fix |
| --- | --- |
| Resolved codec | The browser may not decode it (stale decode measurement). Log out and back in on that device. |
| Exit reason | The app exited. See [Launching a game](/quasar/troubleshooting/launching/). |
| Host frame rate is 0 | Nothing is being produced; the problem is on the host. |

## The picture is corrupt or full of artefacts

| Cause | Fix |
| --- | --- |
| Packet loss (rising loss series in session detail) | A network problem, not the encoder. |
| NVIDIA Vulkan AV1 corruption | Use driver 610 or newer. Where a known codec restriction applies, use HEVC or H.264 if the profile and client support them. See [NVIDIA compatibility](/quasar/reference/nvidia-compatibility/). |
| Vulkan host with HEVC, one frame in four black or torn | Undo any hand-set encode ring depth. `QUASAR_VULKAN_HEVC=1` sets it correctly. |

## No sound

- Check the session detail for degraded audio and its reason.
- Check the audio sidecar image comes from the same release as the agent image.
- Sound in some apps only: the app chose another output device in its own settings.

To fail the session instead of running silently:

```bash
QUASAR_AUDIO_REQUIRED=1
```

## The microphone button is missing or does nothing

| Symptom | Fix |
| --- | --- |
| Missing | Turn it on in **Admin ▸ Settings**. |
| Greyed out | Release input capture first. |
| Does nothing | Allow the browser permission, and use HTTPS. |

A live microphone always shows an indicator.

## The mouse does not move, or moves wrongly

- Capture input (the first item in the drawer).
- Check the host's `uinput` and `input_probe` readiness checks. Rootless: install
  the [device rules](/quasar/install/device-rules/). See [Readiness checks](/quasar/troubleshooting/readiness/#input).
- Pointer offset in a desktop session: update Quasar.

## Escape leaves fullscreen instead of reaching the game

Escape needs a Chromium browser, fullscreen and HTTPS. The drawer says which is
missing; usually it's HTTPS.

## Keyboard input goes to the browser

Capture input. If keys still don't arrive, check `/dev/uinput` as for the mouse.

## Controllers not detected

1. Press a button: browsers hide a gamepad until it sends input.
2. Use HTTPS.
3. Check the `uinput` and `input_probe` readiness checks.
4. Rootless Docker, pad listed but ignored by the game: update the app's image.

## Controller buttons are in the wrong places

Games see an Xbox 360 controller. Some pads (for example 8BitDo over Bluetooth)
aren't reported in the standard layout, and the **Controller & input** pane says
so. Switch the pad to XInput mode, or connect it by cable or USB receiver.

Quasar can translate a pad once someone has captured how their browser reports it,
for that OS and browser. To send a capture, open the browser console (F12) on the
session page, paste this, press a button to wake the pad, then go through every
control slowly. After 60 seconds it copies the result; paste that into the issue.

```js
(()=>{const t0=performance.now(),prev={},out=[];const id=setInterval(()=>{for(const p of navigator.getGamepads()){if(!p)continue;const k=p.index;const s={b:p.buttons.map(b=>+b.value.toFixed(2)),a:p.axes.map(a=>+a.toFixed(3))};const o=prev[k];if(!o){out.push({id:p.id,mapping:p.mapping,buttons:p.buttons.length,axes:p.axes.length,rest:s});console.log("PAD",p.id,p.mapping,p.buttons.length,"buttons",p.axes.length,"axes","rest axes",s.a)}else{s.b.forEach((v,i)=>{if(v!==o.b[i]){out.push({t:Math.round(performance.now()-t0),btn:i,v});console.log("button",i,"=",v)}});s.a.forEach((v,i)=>{if(Math.abs(v-o.a[i])>0.2){out.push({t:Math.round(performance.now()-t0),axis:i,v});console.log("axis",i,"=",v)}})}prev[k]=s}},30);setTimeout(()=>{clearInterval(id);copy(JSON.stringify({ua:navigator.userAgent,platform:navigator.platform,events:out}));console.log("DONE: copied to clipboard",out.length,"events")},60000);console.log("Press any button to wake the pad, then go through every control slowly. Stops after 60 s and copies the result.")})()
```

For just the pad's id and what is pressed right now:

```js
[...navigator.getGamepads()].filter(Boolean).map(p=>({id:p.id,mapping:p.mapping,buttons:p.buttons.length,axes:p.axes.length,pressed:p.buttons.flatMap((b,i)=>b.value>0.5?[i]:[]),axisValues:p.axes.map(a=>+a.toFixed(3))}))
```

## X and Y are swapped on a gamepad page inside the session

A gamepad tester or web game opened in a browser **inside** the streamed desktop
shows X and Y swapped (seen in Firefox). Games and Steam read the pad correctly.
Only web pages in the session that use the browser's Gamepad API are affected. The
virtual pad is not backed by the Xbox kernel driver, so Firefox reads X and Y
differently. This is a known limit; there is nothing to change.

## Touch input on a tablet

Touch is forwarded. Open the session drawer with the on-screen button. Most games
still need a controller.
