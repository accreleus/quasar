The local stack is Postgres, the control plane and the web app, with no node agent
(that needs a Linux GPU host). Use it for UI and API work; streaming work happens
on a GPU host.

<Steps>

1. Clone the repository and its submodules.

   ```bash
   git clone --recurse-submodules https://github.com/accreleus/quasar.git
   cd quasar
   ```

2. Read the project contracts.

   ```bash
   less CLAUDE.md
   less AGENTS.md
   make help
   ```

3. Initialise the checkout (idempotent; never overwrites `.env`).

   ```bash
   make init
   ```

4. Check the environment and configuration.

   ```bash
   make doctor
   make config-check
   ```

5. Start the local stack.

   ```bash
   make up
   make status
   ```

</Steps>

`make dev-web` runs the Vite loop; `make dev-cp` runs the control plane against an
ephemeral Postgres. `make down` stops the stack and keeps its volumes.

## Worktrees and parallel checkouts

Each worktree gets its own `QUASAR_INSTANCE`, Compose project, port block and test
database, so checkouts don't collide. Don't hardcode ports, container names or
project names in new tooling: use the helpers in `scripts/dx/` and expose routine
workflows through the root Makefile.

<Aside type="note" title="Remote warnings from doctor are advisory">
`make doctor` reports degraded when a GPU host is unreachable. The local toolchain
still works.
</Aside>

## Working on this site

```bash
cd site
npm ci
npm run dev
```

`npm run build` builds the production site. It needs the protocol submodule for
the [Control-plane API](/quasar/developer/api/) pages; without `make init`, run
`git submodule update --init protocol` first (`go test ./...` needs it too).

Keep user and operator material out of this developer section.
