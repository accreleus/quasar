This section is for people changing Quasar itself. If you are installing,
administering, or tuning an instance, use the other sections of this knowledge
base. Operating Quasar takes no Go, Rust, or Node toolchain.

The repository, not this site, is the authority for developer workflows. Start
at the root:

```bash
make help
```

Then read `CLAUDE.md` for architecture, invariants, frozen contracts, and current
phase context, followed by `AGENTS.md` for the operating and verification rules.
The complete command catalogue is in `docs/developer-tooling.md`.

<Aside type="caution" title="These pages are an entry point, not a second runbook">
Commands and contracts change with the code; a published site does not. When a
checkout disagrees with what you read here, the checkout wins. `CLAUDE.md`,
`AGENTS.md`, the root `Makefile`, and component documentation stay canonical.
</Aside>

## Repository map

| Path | Responsibility |
| --- | --- |
| `control-plane/` | Go API, authentication, scheduling, signaling, and persistence. |
| `node-agent/` | Rust GPU-host agent, session lifecycle, media pipeline, and app containers. |
| `web/` | React web client and administration interface. |
| `protocol/` | Frozen wire contracts, maintained as a submodule. Generates the [Control-plane API](/quasar/developer/api/) reference. |
| `deploy/` | Compose stacks, image builds, and deployment scripts. The operator front door; it holds only what someone installing Quasar needs. |
| `scripts/dx/` | Canonical developer and diagnostic commands behind the Makefile. New development tooling belongs here, not in `deploy/`. |
| `docs/` | Design records, configuration reference, plans, and developer tooling. |
| `site/` | This Astro/Starlight public knowledge base. |

## The main development loop

1. Initialise and inspect the checkout.
2. Make one bounded change.
3. Run the verification level the files you touched require. Work is not done
   until its build and tests pass at that level.
4. Validate GPU or streaming changes on a real GPU host.
5. Keep commits scoped to one coherent unit of work, and push the branch to
   origin as you go. A local-only branch is invisible to everyone else.

Continue with [Set up a checkout](/quasar/developer/getting-started/).
