## What preparation does

After Steam is installed or updated, Quasar runs it once in a temporary home in the
background, then publishes account-independent files so new users' first launch is
faster. It yields to user sessions. If it fails, Steam still launches normally.

Only supported Steam images are prepared. It doesn't install games, sign in, or share
anyone's home.

## Control it from the Steam source

**Library → Sources → Steam → Prepare Steam for faster first launch**. On by default.
It is separate from Steam discovery and game import.

- **Off:** stops new preparation and seeding, and cancels any in progress. Existing
  homes, sessions and templates are kept.
- **On again:** reuses valid prepared files or schedules preparation. No reinstall
  needed.

Upgrade older node agents before relying on the switch. Explicit host opt-outs still
apply. If homes aren't being prepared, check the per-host status.

## Read the preparation status

Image details show preparation per host, separate from download status. Pending or
running is not ready. Failed or skipped work shows a reason.

Quasar seeds only empty or missing homes. Each user gets their own writable copy. A
home that already has data is never overwritten.

## Reflinks and full copies

Clone mode defaults to **auto**: reflinks where the filesystem supports them,
otherwise a full copy (slower). Image details show which mode was used and why.

A user-share filesystem may reject reflinks even when the pool underneath supports
them. For reflinks, put the home and template mounts on a native filesystem path.
Quasar never moves existing user data, so plan that before changing the paths.

## Advanced host opt-outs

| Variable | Effect on this host |
| --- | --- |
| `QUASAR_TEMPLATE_WARMUP=0` | Doesn't produce templates. |
| `QUASAR_HOME_TEMPLATES=0` | Doesn't use templates. |

Neither overrides the Steam source switch. Most installs don't need them.
