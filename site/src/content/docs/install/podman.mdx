On Podman, Quasar's seed runs as a **Quadlet** unit: a small file that systemd
runs like any other service. The [quick start](/quasar/start/quickstart/) writes
for you to save and start. This page covers host preparation, starting the unit
and checking the installation. Inputs, roles and the recovery actor are the same as on
[Docker](/quasar/install/docker/#what-gets-installed).

## Rootful first

This page is **rootful** Podman (experimental): Podman runs as root. To run Quasar
as an ordinary account instead, follow [Install rootless](/quasar/install/rootless/).
Status per platform: [Container engines](/quasar/start/requirements/#container-engines).

| | Rootful | Rootless |
| --- | --- | --- |
| Unit file | `/etc/containers/systemd/quasar-seed.container` | `~/.config/containers/systemd/quasar-seed.container` |
| Managed by | `systemctl` | `systemctl --user` |
| Socket | `/run/podman/podman.sock` | `$XDG_RUNTIME_DIR/podman/podman.sock` |

<Aside type="caution" title="Socket path, if you write the unit by hand">
The seed only accepts the socket mounted at `/var/run/docker.sock` inside the
container. Use `Volume=%t/podman/podman.sock:/var/run/docker.sock`, which works in
both modes.
</Aside>

## Prepare the host

Once, from an account with `sudo`. The quick start shows the same commands.

```bash
sudo systemctl enable --now podman.socket
sudo systemctl enable podman-restart.service
echo 'd /run/quasar-agent 0755 root root -' | sudo tee /etc/tmpfiles.d/quasar.conf
sudo systemd-tmpfiles --create /etc/tmpfiles.d/quasar.conf
```

| Command | Why |
| --- | --- |
| `podman.socket` | The API the seed talks to. |
| `podman-restart.service` | Brings Quasar's containers back after a reboot: Podman has no daemon to do it. |
| `/etc/tmpfiles.d/quasar.conf` | Makes the agent's runtime directory at every boot. `/run` is emptied on reboot and Podman, unlike Docker, never creates a missing mount source, so without it the agent can't start after a reboot. |

**NVIDIA:** complete [NVIDIA setup for Podman](/quasar/install/nvidia/#podman-rootful)
before deploying. It includes CDI device generation, verification and SELinux policy.

**Check it worked:** `systemctl is-enabled podman.socket podman-restart.service`
says `enabled` twice, and `ls -ld /run/quasar-agent` shows the directory.

Optional: [console mode](/quasar/admin/console/) needs the console rules from
[Device rules](/quasar/install/device-rules/), and the [UDP send
buffer](/quasar/tuning/latency/#the-udp-send-buffer) makes streams smoother.

## Installing

1. In the [quick start](/quasar/start/quickstart/), choose **Podman** and download the Quadlet configuration from **Result**.
2. Save it as `/etc/containers/systemd/quasar-seed.container`, then load and start it:

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl start quasar-seed
   ```

The compatible seed resolves image tags to immutable digests on first install.
Keep the machine-state volume and user homes when changing the unit.


## Adding a GPU host

Run the [Add host](/quasar/install/second-host/) command **as root** (`sudo -i`,
then paste it). Rootful Podman's socket is visible to root only, so from an
ordinary account, even one with `sudo`, the command reports *no container engine
found*.

## Check it came up

```bash
sudo systemctl status quasar-seed
sudo podman logs quasar-seed
sudo podman exec quasar-recovery quasar-recovery status
```

The recovery actor's `status` is the most useful: it reports the install itself.
Then continue with [Create your account](/quasar/install/first-run/), using
`sudo podman` where it says `docker`.

## Boot behaviour

- The Quadlet unit starts the seed at boot.
- `podman-restart.service` brings Quasar's other containers back. Without it they
  stay stopped after a reboot.
- `/etc/tmpfiles.d/quasar.conf` recreates `/run/quasar-agent`. Without it the agent
  fails after a reboot with `cannot stat /run/quasar-agent`.

## Rootless: a session as the quasar account

Rootless commands need a full systemd user session for `quasar`. `sudo -u quasar`
is not enough:

```bash
sudo machinectl shell quasar@
```

Then use `systemctl --user` and `podman` without `sudo`. Exit normally when done;
lingering keeps Quasar running. If an install or update stalls waiting for health
checks, the account has no user session yet: open one this way. Setup:
[Install rootless](/quasar/install/rootless/).
