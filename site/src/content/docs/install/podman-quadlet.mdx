On Podman, Quasar's seed runs as a **Quadlet** unit: a small file that systemd
runs like any other service. The [quick start](/quasar/start/quickstart/) writes
and starts it for you. This page covers doing it by hand and working with it
afterwards. Validated platforms: [Engine profiles](/quasar/start/engine-profiles/).

## Rootful or rootless

The same unit file works in both modes:

| | Rootful | Rootless |
| --- | --- | --- |
| Unit file | `/etc/containers/systemd/quasar-seed.container` | `~/.config/containers/systemd/quasar-seed.container` |
| Managed by | `systemctl` | `systemctl --user` |
| Runs as | root | the `quasar` account |
| Socket | `/run/podman/podman.sock` | `$XDG_RUNTIME_DIR/podman/podman.sock` |

Rootless is the [mode Quasar targets](/quasar/start/engine-profiles/#root-equivalence).

<Aside type="caution" title="Socket path, if you write the unit by hand">
The seed only accepts the socket mounted at `/var/run/docker.sock` inside the
container. Use `Volume=%t/podman/podman.sock:/var/run/docker.sock`, which works in
both modes.
</Aside>

## Installing

First run [host preparation](/quasar/install/prepare-host/)
(`prepare-host.sh --mode rootless --engine podman`, or `--mode rootful`).
Without it, nothing survives a reboot.

<Steps>

1. **Quick start (recommended).** Pick Podman, rootful or rootless, and go to
   **Result**. Run the script it shows as `quasar` (rootless) or root (rootful).
   It resolves the image digests and installs the unit.

2. **Or by hand.** The Result step also shows the unit with placeholder digests.
   Resolve them with `podman pull` and `podman image inspect`, fill in the
   `Image=` and `Environment=QUASAR_*_IMAGE=` lines, write the file to the path
   above, then:

   ```bash
   # rootless, as the quasar account
   systemctl --user daemon-reload
   systemctl --user start quasar-seed
   ```

   ```bash
   # rootful
   sudo systemctl daemon-reload
   sudo systemctl start quasar-seed
   ```

</Steps>

## Getting a rootless session as the quasar account

Rootless commands need a full systemd user session for `quasar`. `sudo -u quasar`
is not enough.

```bash
machinectl shell quasar@
```

Exit normally when done; lingering keeps Quasar running.

## Status and logs

```bash
# rootless, as quasar
systemctl --user status quasar-seed
podman logs quasar-seed
podman exec quasar-recovery quasar-recovery status
```

```bash
# rootful
sudo systemctl status quasar-seed
sudo podman logs quasar-seed
sudo podman exec quasar-recovery quasar-recovery status
```

The recovery actor's `status` is the most useful: it reports the install itself.

## Only trying it out

For a quick look without Quadlet, the Result step's "only trying it out" section
has a bare `podman run`:

```bash
podman run -d --name quasar-seed --restart unless-stopped \
  --security-opt label=disable \
  -v "$XDG_RUNTIME_DIR/podman/podman.sock:/var/run/docker.sock" \
  -v quasar-machine:/var/lib/quasar-machine:ro \
  ... \
  <seed image> seed
```

It is less reliable across reboots. Use the Quadlet unit for anything you keep.

## Boot behaviour

- The Quadlet unit restarts under systemd. Rootless, it needs the `quasar`
  account's lingering (host preparation enables it).
- `podman-restart.service` brings containers back after Podman restarts. Host
  preparation enables it.
- If an install or update stalls waiting for health checks, the `quasar` account
  has no user session yet. Run `machinectl shell quasar@` to start one.
