## The updater service

The stack has four services, not three: `quasar-updater` sits beside the control
plane and the agent so Quasar can update itself from the admin console. A
container cannot recreate itself, which is why something else has to.

It holds the Docker socket, so it is worth knowing what it will not do. It pulls
only digests inside `QUASAR_UPDATER_ALLOWED_NAMESPACES` (the project's own
registry namespace unless you narrow it), and it recreates only the two Quasar
services in the stack it was started beside — which it discovers from its own
compose labels. It builds nothing, runs no arbitrary command, and never touches
Postgres, your game containers, or anything else on the machine.

`QUASAR_STACK_DIR` above must be this directory's absolute host path. Left unset,
Compose refuses to start this generated stack and asks you to set the path.
It must point to your existing deployment files, not an empty directory.

<Aside type="tip" title="Podman">
Set `QUASAR_DOCKER_SOCKET=/run/user/<uid>/podman/podman.sock`. The service
already ships `security_opt: ["label=disable"]`, without which an
SELinux-enforcing host refuses every call to the mounted socket.
</Aside>

Deleting the service from the file is a supported choice: everything else works,
the host simply reports that it has no updater and you upgrade it by hand. See
[Upgrading](/quasar/operations/upgrading/) and [Updating
Quasar](/quasar/admin/releases/).

## Updating

Images in this installation are explicitly pinned. Pulling the same digest does
not select a new release. Use **Admin → Fleet → Releases** to review and apply
available updates with sessions drained first; see [Updating
Quasar](/quasar/admin/releases/).

For a manual update, read [Upgrading](/quasar/operations/upgrading/), then replace
the control-plane and agent pins in `deploy/.env` with the new release's digest
references. Use that release's published updater version where required. Do not
use an invented tag or assume `latest` exists.

```bash
docker compose -f deploy/docker-compose.yml config --quiet
docker compose -f deploy/docker-compose.yml pull
docker compose -f deploy/docker-compose.yml up -d
```

Keep a backup of the existing pins and follow the documented database migration
limits when considering a rollback.

## Building from source

For contributors, and for hosts tracking a development branch. Roughly 25
minutes and 25 GB of build storage on 8 vCPU. Start at
[Set up a checkout](/quasar/developer/getting-started/) and use the Makefile
rather than adapting anything above.

## Ports

| Port | Purpose |
| --- | --- |
| 8443 | HTTPS web app and API. Change with `QUASAR_TLS_PORT`. |
| 8080 | Agent enrollment and `/health`. Browser routes redirect to HTTPS. Change with `CONTROL_PORT`. |

There is no reverse proxy in the default deployment. For Caddy or an existing
ingress, see [Behind a reverse proxy](/quasar/network/reverse-proxy/).

## Stopping without losing data

```bash
docker compose -f deploy/docker-compose.yml down
```

Leave `-v` off unless you mean to delete the database and the agent state. Save
data stays on its host path. Certificates and artwork are in the control-plane
named volume, which `down` preserves unless you also request volume removal.
