An **engine profile** is a platform plus a container engine (Docker or Podman) in
one mode: **rootful** (runs as root) or **rootless** (runs as an ordinary account).
The quick start, the add-host command and each host's readiness card all use this
table.

<EngineProfiles />

- **Supported**: tested end to end (sessions, input, audio, updates, reboot).
- **Experimental**: expected to work, not yet fully tested. Allowed.
- **Unsupported**: untested or known not to work. The quick start and the add-host
  command refuse it and suggest an alternative.

Hover a badge for the reason. Rootful Docker works everywhere, including Unraid.
GPU support is separate: see [Requirements](/quasar/start/requirements/#gpu).

## Root equivalence

A rootful engine's socket is root on that machine, and Quasar holds it on a rootful
install, like any container manager does. To avoid that, use rootless Docker or
rootless Podman.

For the same reason the node agent runs with `--security-opt label=disable` on
SELinux hosts: the socket is already the privilege boundary. Game sessions stay
confined.

## Rootless Docker and home ownership

On rootless Docker, files in user homes are owned on the host by a subordinate uid
rather than the `quasar` account, so `ls -n` shows a large number as owner. This is
harmless, and the `homes_root_writable` readiness check notes it. Rootless Podman
maps them to `quasar`.

Don't `chown -R` the homes to change this. To switch engines, see
[Moving to rootless](/quasar/install/move-to-rootless/).
