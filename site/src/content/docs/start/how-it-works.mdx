Quasar runs games on your GPU server and brings them to your browser. A first
install puts everything on one host; you can add another computer as your library grows.

<ArchDiagram caption="Management goes through the control plane. The game stream connects your browser directly to the GPU host." />

## Press Play

1. Your browser asks the **control plane** to start an app.
2. The control plane selects an available **GPU host** and compatible stream settings.
3. The host's **node agent** starts the game.
4. Your browser connects directly to that host for video, audio and input over WebRTC.

The web app uses the control plane's API for accounts, the library and session
management. The direct host connection carries the stream, so every GPU host
must be reachable from your browser over your LAN or VPN.

## What runs on your server

- **Control plane:** serves the web app and manages accounts, the library and sessions. Its data lives in Postgres.
- **Node agent:** runs apps and streams them from a GPU host. Each additional GPU server has its own agent.
- **Installation and recovery:** you declare one seed container. It keeps a recovery service running to install, update and recover that machine's Quasar services. Persistent machine state and user homes must be kept.

See the [glossary](/quasar/reference/glossary/) for app, host, session and quality
profile terminology, or go straight to the [quick start](/quasar/start/quickstart/).
