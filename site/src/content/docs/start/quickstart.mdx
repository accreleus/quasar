A few questions, then one command to run on the machine, or one stack to paste
into Dockge or Arcane. You need Linux, Docker or Podman, and about 20 GB of disk;
the [requirements](/quasar/start/requirements/) have the detail.

The **Engine** step picks the container engine and its mode, and shows the status
of each [engine profile](/quasar/start/engine-profiles/) for your platform. An
unsupported combination cannot go further. Except on Unraid, the result starts
with [host preparation](/quasar/install/prepare-host/): fetch the script, check its
checksum, run it as root. Then comes the install itself, a script for Docker or a
Quadlet unit for Podman.

Either way the machine runs one container you declare, the **seed**. It creates
Quasar's **recovery actor**, which generates every secret on the machine and
creates Postgres, the control plane and, on a machine with a GPU, the node
agent. Nothing sensitive is on this page to leak, and nothing here writes an
`.env` of secrets. [Install Quasar](/quasar/install/install/) says the same in
prose, with every input.

<Aside type="note" title="Stable releases">
The script pins the current stable release's images by digest, so the install
never moves on its own: it updates when you apply an update from the admin
console, and it follows the **stable** channel. An install made before the first
stable release is on `edge`: see [Moving an edge install to
stable](/quasar/admin/releases/#moving-an-edge-install-to-stable).
</Aside>

<Aside type="note" title="Already running Quasar from the Compose files?">
The script stops if it finds one. To keep your accounts, library and settings,
follow [Move a Compose install](/quasar/install/move-existing/) instead of this
script: it dumps the old database first and loads it into the new install.
</Aside>
