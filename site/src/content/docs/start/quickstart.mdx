A few questions, then one command to run on the machine, or one stack to paste
into Dockge or Arcane. You need Linux, Docker and about 20 GB of disk; the
[requirements](/quasar/start/requirements/) have the detail.

Either way the machine runs one container you declare, the **seed**. It creates
Quasar's **recovery actor**, which generates every secret on the machine and
creates Postgres, the control plane and, on a machine with a GPU, the node
agent. Nothing sensitive is on this page to leak, and nothing here writes an
`.env` of secrets. [Install Quasar](/quasar/install/install/) says the same in
prose, with every input.

<Aside type="caution" title="Edge builds only">
Installs owned by Quasar ship on the **edge** channel, which follows the
`develop` branch. There is no stable release of them yet. The script pins the
edge channel's current images by digest, so the install never moves on its own:
it updates when you apply an update from the admin console.
</Aside>

<Aside type="note" title="Already running Quasar from the Compose files?">
Nothing converts that install. The script stops if it finds one. See [Replace a
Compose install](/quasar/install/move-existing/).
</Aside>
