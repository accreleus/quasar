Five questions, then one command to run on the machine with the GPU. You need
Linux, Docker and about 20 GB of disk; the
[requirements](/quasar/start/requirements/) have the detail.

Everything here runs in your browser. The script makes its own secrets on the
target machine, so nothing sensitive exists on this page to leak.

What you run declares **one container, the seed**. It starts Quasar's recovery
actor, which creates Postgres, the control plane and the node agent through the
Docker Engine API, and later updates them from the admin console. There is no
compose file for those services and no `.env`: the recovery actor generates the
secrets itself and keeps them in the `quasar-machine` volume. The recovery actor
holds the Docker socket, so it is worth saying what it cannot do: it pulls only
digests inside the allowed registry namespace, and it acts only on containers it
created. [Install Quasar](/quasar/install/install/) has the detail.

{/* TODO(#365): the next paragraph describes the format-1 manifest and the updater image. After #365 the installer reads the format-2 manifest and pins the seed (the recovery-actor component) by digest. */}

The installer selects a stable release, pins its control-plane and agent image
digests, and checks the matching updater image before starting anything. If the
stable release predates this installer configuration, it stops with instructions
to use that release’s installation guide or wait for a compatible release.
Development changes described here are not available merely because they have
merged into `develop`.
