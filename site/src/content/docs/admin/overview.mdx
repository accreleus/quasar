## How admin access is enforced

The server checks the admin role on every admin API call. Hiding `/admin` from
non-admins is only for tidiness; typing the URL gets a page that loads no data.

The first admin is created through the first-run wizard's setup token. A legacy
Compose install or source checkout can instead set the `BOOTSTRAP_ADMIN_*`
environment variables. Registration only creates ordinary users.

## The map

| Entry | What it holds |
| --- | --- |
| **Overview** | Readiness checklist for a new instance, fleet GPU capacity, recent failures. |
| **Settings** | Registration, library discovery, allowed browser origins, artwork credentials, microphone permission, other access settings. |
| **Sessions** | Live and past sessions, with metrics, traces and diagnostic bundles. |
| **Audit log** | Admin actions. |
| **Fleet** | **Hosts** (GPUs, capacity, per-host settings including storage roots, console), **Storage** (managed homes), **Jobs** (background work and schedules). |
| **Library** | **Apps**, **Runtime presets**, **Images** (installed across hosts), **Sources** (Steam, manual apps, artwork). |
| **Streaming** | **Launch profiles** (tiers users pick), **Stream profiles** (encode rungs). |
| **People** | **Users** (roles, session limits), **Invites** (registration mode, codes). |

## A sensible order for a new instance

1. Check hosts and GPUs under **Fleet ▸ Hosts**.
2. Install images under **Library ▸ Images**.
3. Create apps under **Library ▸ Apps**.
4. Check the tiers under **Streaming ▸ Launch profiles**.
5. Set the registration mode and invite people under **People ▸ Invites**.
6. Play something, then check it under **Sessions**.

## What the admin area does not do

- Install games. Quasar launches container images; the
  [Steam library](/quasar/admin/steam/) is the closest to automatic.
- Manage the host OS: drivers, kernel modules and the socket buffer sysctl are yours.
