- A **stream profile** is one encode rung: codec, resolution, frame rate, bitrate,
  and the thresholds a client must meet. Users never see these.
- A **launch profile** is an ordered list of stream profiles, best first. Users
  pick these (for example "1080p60").

## How a session resolves

At launch the server takes the first rung in the chosen launch profile that:

1. the host can encode,
2. the client can decode (measured at login),
3. has not failed for this client before,
4. has hardware encode available, if the rung requires it.

See [Codecs](/quasar/tuning/codecs/#how-the-server-picks) for details.

Every launch profile must contain at least one H.264 rung, so a launch always has
something playable. The server rejects a profile without one.

## What ships by default

Twelve launch profiles: 720p, 1080p, 1440p and 4K at 60, 90 and 120 fps.
**1080p60 is the recommended default.**

Each tier's rungs go AV1, then HEVC, then H.264:

| Codec | Bitrate saving vs H.264 | Browser support |
| --- | --- | --- |
| AV1 | about 40 to 50% | Chrome everywhere |
| HEVC | about 30 to 40% | Chrome with OS hardware support (usually macOS and Windows, never Linux) |
| H.264 | none | everywhere |

The saving matters on a constrained link, not on a fast LAN.

<Aside type="caution" title="4K120 does not work in a browser">
Browser decode can't keep up. Treat it as waiting on the native client.
</Aside>

## When to change any of this

Usually don't. Reasons you might:

- **Cap quality**: remove high tiers, or restrict apps to specific tiers, so one
  user can't take a whole GPU at 4K120.
- **Suit your network**: lower bitrates for a constrained link.

Rungs your GPU can't encode are skipped automatically; no need to remove them.

## Instance default and user override

Under Admin you set the instance default launch profile and whether users may
override it. With overrides on, a user's own default (account page) wins.

## What the user sees

A tier name and whether it suits their device. The codec, bitrate and rungs are in
the session detail under **Admin ▸ Sessions**.
