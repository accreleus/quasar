Every app runs in a container image. Admin, Library, Images installs images onto
your hosts and keeps them up to date, pinned to exact versions so every host runs
the same bits.

## Where images come from

The list comes from the catalog published by the `quasar-images` project. Each
entry is one of:

- **Prebuilt**: pulled from a registry. The tag is resolved to a digest at sync
  time, so a moving tag can't change what runs.
- **Template**: a Dockerfile built on each host from a pinned commit, only when you
  ask.

## Installing an image

Press install. Each host pulls or builds on its own, and progress shows per host.

Installing also creates a **runtime preset** (image, environment, GPU access,
mounts) that apps reference, so install the image before creating its app.

## Where images get placed

An image is prepared on the hosts its apps may launch on, per each app's
[Placement](/quasar/admin/apps/#placement) tab. By default that's every eligible
host.

With **Pull on first launch**, a host prepares the image at its first launch there
instead. The player sees the loading screen meanwhile, which can take minutes for
a large image. A failure fails only that launch. Use it for large, rarely used
images.

## Removing cached versions

Uninstalling an image removes Quasar's record of it; its apps stop launching until
it's reinstalled. Nothing is deleted from the hosts.

On the image's page, **Cached versions** lists each version per host. **Remove this
cached version** deletes it from that host. It's refused while anything still needs
that version: an app, any container (even stopped), pending work, the last version
that prepared successfully, or an incomplete host inventory. The page shows
**Removal confirmed by the host inventory** when it's done. Managed homes are never
touched.

## Updates

Set the policy under Admin, Settings:

| Policy | Behaviour |
| --- | --- |
| `notify` | Default. Tells you an update exists and waits. |
| `manual` | You update when you choose. |
| `auto` | Updates apply as they appear. |

**Pin** an image to hold it at its current version. Updates take effect at the next
launch, never in a running session.

<Aside type="caution" title="There is no rollback">
The previous version isn't kept. To go back you re-pull or rebuild an older
version. If a version works for you, pin it.
</Aside>

## Registry allowlist

`QUASAR_IMAGE_REGISTRY_HOSTS` (default `ghcr.io`) limits which registries Quasar
resolves digests and artwork from. Widen it only for your own registry.

## If an install stalls

Open Admin, Fleet, Jobs and check the image job's latest run. An unresolved digest
usually means the registry is unreachable, not on the allowlist, needs credentials,
or the image reference is malformed.

## Using your own image

**Every app image must derive from Quasar's graphics layer**, which supplies GPU
access and the Wayland pieces the compositor needs. An arbitrary Docker Hub image
won't work. Images also carry contract labels, validated on entry. To build images
in the family, see [GPU and remote workflows](/quasar/developer/gpu-workflows/).
