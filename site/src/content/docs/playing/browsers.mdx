## The short answer

Use Chrome, or a Chromium-based browser such as Edge or Brave, on a desktop OS,
over HTTPS.

## Why Chrome

Quasar is developed and tested against Chrome:

- **Keyboard Lock** (Escape reaches the game) is Chromium-only.
- **Codec rules** are based on Chrome's decoders.
- **Gamepad** support is tested against Chrome's Gamepad API.

Firefox and Safari are untested. Parts may work; nothing is promised.

## HTTPS is not optional

| Feature | Without HTTPS |
| --- | --- |
| Gamepad support | Controllers are not detected. |
| Keyboard Lock | Escape leaves fullscreen instead of reaching the game. |
| Microphone | Cannot be enabled. |

The default install serves HTTPS on port 8443 with a self-signed certificate.
Accept the browser warning once. See [HTTPS and certificates](/quasar/network/https/).

## Codecs, and what your browser can decode

Quasar measures what your browser can decode when you log in, and never sends
something it can't play.

- **H.264** works everywhere. Every quality tier falls back to it.
- **AV1** works everywhere Chrome runs, with a software fallback if there is no
  hardware decoder.
- **HEVC** needs hardware decode from the OS; Chrome has no software fallback.

| Client OS | HEVC |
| --- | --- |
| macOS | Almost always works. |
| Windows | Usually works, depending on the GPU. |
| Linux | Effectively never. |

If HEVC is unavailable, Quasar uses the next codec down.

<Aside type="note" title="H.264 High profile does not decode in any browser">
Browser sessions use constrained-baseline H.264. This is handled automatically.
</Aside>

## Mobile and tablets

Touch devices get an on-screen menu button and touch input is forwarded. Most
games need a paired controller to be playable.

## Nothing to install

No launcher, extension or client binary. A native client is planned; the browser
is the only client today.
