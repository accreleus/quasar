The control plane can sit behind a proxy. The stream never goes through it, so
see [Reaching Quasar remotely](/quasar/network/remote-access/) before expecting
internet play.

## On an owned install

Point your existing proxy at the control plane's **HTTP** port (8080 by default),
not 8443. The examples below use `quasar.example.com` and a control plane at
`quasar.lan:8080`; replace both with your addresses.

- **Pass the original `Host` and send `X-Forwarded-Proto`.** The signaling address
  is built from them; owned installs have no `PUBLIC_BASE_URL`. The examples below do this.
- **Add the public URL to allowed origins** in **Admin ▸ Settings**. Opening
  first-run setup through the public address saves it for you. There is no
  environment override on an owned install.
- **Set `QUASAR_TRUSTED_PROXIES`** (a seed input) to your proxy's address or CIDR.
  To change it later, on the first machine:

  ```bash
  docker exec -it quasar-recovery quasar-recovery reconfigure --yes QUASAR_TRUSTED_PROXIES=<address or CIDR>
  ```

Keep `QUASAR_PUBLIC_HOST` for direct LAN access on the HTTPS port.

## On a legacy Compose install

The hardened overlay puts Caddy with ACME certificates in front and derives the URL
and origins from `QUASAR_PUBLIC_HOST` in `deploy/.env`:

```bash
docker compose -f deploy/docker-compose.yml \
               -f deploy/docker-compose.hardened.yml up -d
```

With your own proxy, set these in `deploy/.env`.

### PUBLIC_BASE_URL

```bash
PUBLIC_BASE_URL=https://quasar.example.com
```

Needed when the proxy rewrites `Host`.

### Allowed origins

```bash
QUASAR_ALLOWED_ORIGINS=https://quasar.example.com
```

Gates the signaling WebSocket. Unset uses the list in **Admin ▸ Settings**; set
(even empty), it overrides that list. With neither, only same-origin is allowed.

- Comma-separated exact `scheme://host[:port]` entries, no path, query or credentials.
- `*` is rejected. A malformed entry stops startup.
- Keep your LAN origins (such as `https://<lan-ip>:8443`) when adding a public one.

### QUASAR_TRUSTED_PROXIES

The proxy's address or network, and nothing broader. With the bundled Caddy, use
that Compose project's bridge subnet. Empty is safe: forwarded addresses are ignored.

## Proxy requirements

- Forward WebSocket upgrades on `/v1/signal` and `/agent/ws`.
- No buffering on those paths.
- A long read timeout (a 60-second idle timeout cuts sessions).
- Send `X-Forwarded-Proto`.

## What not to proxy

Point node agents on the same machine or trusted network at the control plane
directly (`/agent/ws` over HTTP), not through the proxy.

When your proxy already compresses responses, set `QUASAR_COMPRESSION=false`
on the control plane so the same bytes aren't gzipped twice.

## Checking it worked

1. Open the console at the proxy address and run Admin's access check.
2. Connect through your LAN or VPN and launch a session.
3. Confirm video, sound and input work. If the session never starts, check
   allowed origins and the client's direct route to the host.
