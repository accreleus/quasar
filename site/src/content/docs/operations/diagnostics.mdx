---
title: Diagnostics
description: Taking a diagnostic bundle, what is in one, and how to read the verdict.
---

When a session was bad, take a diagnostic bundle. It lines up what the encoder,
the network and the client were doing over the same window and says which one
was likely responsible.

## Taking one

In **Admin ▸ Sessions**, open the session and take a bundle. Or, with an admin
token:

```bash
curl -s "https://<host>:8443/v1/admin/sessions/<session-id>/diagnostic-bundle" \
  -H "Authorization: Bearer $TOKEN" > bundle.json
```

The window defaults to five minutes (range two to ten).

Take it soon: a running session keeps one hour of telemetry, and an ended one
keeps it for 24 hours by default.

## What is in one

| Part | Contents |
| --- | --- |
| Metrics | Encode time, frame rate, ABR setpoint, round trip time, packet loss, client presentation variation. |
| Events | Bitrate retargets, freezes, WebRTC state changes, playout buffer changes. |
| Clock alignment | Host-to-browser clock offset. If unmeasured, end-to-end latency figures aren't trustworthy. |
| Derived windows | Hitches, bitrate downshifts, encoder saturation, likely congestion. |
| Verdict | See below, with a short list of evidence. |

## Reading the verdict

| Verdict | Meaning |
| --- | --- |
| `nominal` | Nothing wrong found, tab visible. |
| `likely_network_congestion` | Loss and round trip time rose with a bitrate downshift. |
| `likely_encoder_saturation` | Encode time at or above the ceiling while frame rate was steady. |
| `likely_client_presentation_limit` | The client presented frames unevenly; encode and network looked clean. |
| `indeterminate_client_hidden` | The browser tab was hidden. Reproduce with it visible and take another bundle. |
| `unknown` | Doesn't fit the cases above. |

The verdict is informational; nothing acts on it. New values may appear.

## The thresholds it uses

| Signal | Threshold |
| --- | --- |
| Encode time, 95th percentile | 16 ms and above is saturation |
| Presentation interval variation | 18 ms and above contributes to a hitch (after warm-up, repeated) |
| Round trip time, 95th percentile | above 50 ms contributes to congestion |
| Cumulative packet loss rise | above 5 packets contributes to congestion |
| Host frame rate, 10th percentile | below 50 fps means the encoder is not steady |

## Annotations

You can add a note to a session's timeline. Annotate a mid-session setting change
so it shows up next to its effect in the bundle.

## Comparing two runs

There is no built-in comparison. Take a bundle for each and change exactly one
thing: same app, tier, client, network and similar content.

## What to attach to a bug report

For a session problem, the diagnostic bundle. For install or startup problems,
a redacted state dump from a checkout:

```bash
make diagnose-bundle
```
