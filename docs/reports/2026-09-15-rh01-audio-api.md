## Behavior

The PulseAudio sibling caller uses the owned runtime API for creation, explicit termination and cleanup. Each launch attempt records its own operation before mutation. Docker ownership verification and final exit/log collection precede removal. An uncertain stop preserves the socket directory and a durable cleanup obligation. Ordinary audio recovery retries pending cleanup; agent startup explicitly retires recorded audio from the previous process. Diagnostic recovery cannot terminate live audio.

The audio image override and running-agent-image default remain. The fixed profile retains network isolation, UID:GID 0:0, cap-drop ALL, no-new-privileges, PID limit 512, writable root and one same-path writable socket-directory bind. The existing output sink, microphone feed/remap, anonymous non-root socket access and private Pulse runtime directory remain. A socket readiness timeout still returns the intentional silent fallback, after requesting cleanup. Readiness probes use nonblocking Unix sockets so a full listener backlog cannot defeat the two-second readiness bound.

Directory cleanup happens only after the exact container is known absent. A recorded, uniquely named retirement directory preserves cleanup identity across interrupted deletion and replacement of the original socket path. CLI cleanup preserves Pulse names: application containers remain on their existing CLI path.

## Deployment cutover

Pre-migration CLI Pulse containers have no API operation journal. They are deliberately not adopted by the API or deleted by the new CLI orphan sweep. Before the first candidate deployment, wait until the target has no active sessions and stop sessions normally using the old agent. Inventory remaining `quasar-pulse-*` containers. For any legacy orphan, verify its existing `io.quasar.agent-owner` label against that target agent's established identity, capture its immutable ID and final logs/exit, then explicitly retire only that verified orphan as part of the approved cutover. Preserve foreign/unlabelled containers and report collisions for operator review. Never use a prefix-wide force removal.

Before rolling back to an agent from before #234, stop candidate sessions and confirm their API-owned audio cleanup. The older CLI sweep does not understand these journals; an unverified cleanup obligation is a reason to preserve the candidate and its state for recovery, not to launch the older sweep.

This one-time cutover belongs in the concrete remote approval package. It is not an automatic runtime fallback. Preserve persistent identity, shared homes, volumes and unrelated workloads. No agent update is permitted while a user session would be interrupted without separate approval.

## Required real-session acceptance

Remote execution requires explicit approval for `gpu-test`, the exact locally built candidate and the actions below. Build with `deploy/build-images.sh`, preserve existing image tags/cache, retain the unchanged image contract and record CPU-host GPU skips separately. Transfer the resulting immutable image with checksum verification; do not rebuild it on the target or trigger GitHub Actions.

1. Record target image/ref, idle session state and persistent identity without exposing secrets. Apply the approved legacy cutover if needed. Load the candidate and recreate only the intended node-agent service using its existing mounts/environment; retain the previous image for recovery.
2. Launch one temporary session through the normal API using an existing application. Record its SID, exact application/audio container IDs and socket directory. Verify effective audio is not degraded.
3. Emit a bounded known tone **from the application container** through its configured `PULSE_SERVER` and output sink. Attach the browser using the candidate's `scripts/harness/peer-driver.mjs` with `AUDIO_PROBE=1` in normal measurement mode. Supply the normal SID/signaling/auth coordinates without printing credentials. Record the driver checksum. The current external `qses` wrapper does not forward `AUDIO_PROBE`; setting that variable on the wrapper alone is insufficient.
4. Require advancing audio bytes, packets, decoded duration and decoded energy for the same inbound stream, a connected peer/live audio receiver, and an unmuted, playing audio element without a playback error. Keep the tone active across the probe's two-second sample. Video decode alone does not satisfy this check.
5. Stop that SID through the normal API. Require the exact app/audio IDs and owned socket/retirement directory to disappear within 35 seconds of acknowledged stop, with completed journal evidence and retained final audio logs/exit. Record actual duration. Verify unrelated workloads and persistent data remain.
6. Stop the temporary session and tone on every failure path. Unverified cleanup remains explicitly pending; do not delete backing paths to make the check pass.

Remote audio, GPU image assertions and real-session bounded teardown remain unverified until this procedure passes. No promotion to develop/main, #235 work or ticket closure is authorized by local success.
