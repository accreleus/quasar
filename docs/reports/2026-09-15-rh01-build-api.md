## Delivered behavior

Managed image jobs call `RuntimeClient::build_image` with Quasar-owned request and
result types. The private Bollard adapter explicitly selects the classic builder,
keeps cache and intermediate-container behavior, sends build arguments and existing
registry logins, consumes progress/errors, and verifies the resulting image before
reporting ready. The old CLI build process, output scraper, and final CLI size
inspection have been removed. Disk metadata and other unmigrated CLI callers remain.

Existing HTTPS source restrictions, extraction limits, Dockerfile validation,
per-image ordering, latest pending replacement and shared pull/build permits remain.
The context packager applies root `.dockerignore` rules and streams an owned temporary
tar. Its matching logic adapts the Linux behavior of
[Moby patternmatcher](https://github.com/moby/patternmatcher/tree/5a6d8429a19bb6948a372ff19e86fe83599a04b7),
with the Apache-2.0 license retained beside the module. Matching fixtures cover
recursive patterns, character classes, root anchoring, negation, BOM/comments and
required Dockerfile/ignore inclusion. The builder selection follows Docker's
[legacy-builder documentation](https://docs.docker.com/reference/cli/docker/image/build/).

Progress has one replaceable snapshot and a bounded partial line. Local diagnostics
retain a 4 KiB tail; raw build logs and credential contents never become wire errors.
The one-hour job deadline is independent of output and covers download through
verification. Terminal image-job results survive a disconnected or full
control-plane channel through the existing reconnect/heartbeat replay.

Before submission, the adapter persists a unique operation label and a fingerprint
of the exact context, Dockerfile, tag and arguments. A matching resulting image proves
completion after a lost response. An old or absent image does not authorize a second
uncertain build. Definite build errors permit a corrected retry. Dropping observation
or reaching a deadline does not promise Docker rollback or intermediate cleanup.
Recovery instructions are in [configuration.md](../configuration.md#node-agent--app-container--runtime).

**Specification:** no outstanding findings. Review caught a difference between
Docker and Rust regex character classes that could upload an ignored file. A failing

`[a&&b].txt`, `[[]` and `[x~~y].txt` cases, and the reviewer cleared the correction.

## Reproducing local Docker acceptance

On the explicitly selected local Docker test host with the existing agent development
image, from the repository root:

```sh
docker run --rm --network host \
  -v "$PWD":/workspace \
  -v /var/run/docker.sock:/tmp/quasar-engine.sock \
  -e QUASAR_TEST_RUNTIME_SOCKET=/tmp/quasar-engine.sock \
  -e QUASAR_TEST_RUNTIME_IMAGE=quasar-agent-dev:latest \
  -w /workspace/node-agent quasar-agent-dev:latest \
  cargo test --lib runtime:: -- --include-ignored --nocapture
```

This includes the earlier discovery and image pull/removal acceptance tests. Only
unique fixture assets are mutated. No global image or cache pruning is part of the
fixture; classic builder cache/intermediates follow the existing builder policy.
