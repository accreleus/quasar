## Delivered behavior

Assignment preparation and catalog image pull/removal use Bollard through Quasar
runtime types. Local images are reused; pull progress is coalesced and bounded,
stream failures are consumed, and successful inspection is required before ready.
Existing per-image ordering, latest pending replacement, and reconnect replay remain.
Terminal delivery cannot hold image workers behind a full control-plane channel;
undelivered states retry on heartbeat and reconnect.

Assignment launch observes preparation completion and failure. Cancellation stops
observation without abandoning the underlying bounded mutation. Verified assignment
launches require a local image, preventing an implicit CLI pull. This policy is
internal to the node agent; no protocol changes were made. Swap, warm-up and standalone
callers retain their existing CLI policy until their designated migration slices.

Removal checks running and stopped container references, requests non-forced deletion
without parent pruning, and verifies absence. Synced intents preserve uncertainty
across process/transport failure. Retry reconciles observed state and refuses another
mutation when the prior outcome remains unknown. Registry login configuration and
installed credential helpers remain usable; credentials and raw engine failures do
not enter public error messages. Recovery details are in
[configuration.md](../configuration.md#node-agent--app-container--runtime).

## Reproducing Docker acceptance

From the repository root, on an explicitly selected local Docker test host with the
existing `quasar-agent-dev:latest` development image:

```sh
docker run --rm --network host \
  -v "$PWD":/workspace \
  -v /var/run/docker.sock:/tmp/quasar-engine.sock \
  -e QUASAR_TEST_RUNTIME_SOCKET=/tmp/quasar-engine.sock \
  -e QUASAR_TEST_RUNTIME_IMAGE=quasar-agent-dev:latest \
  -w /workspace/node-agent quasar-agent-dev:latest \
  cargo test --lib runtime:: -- --include-ignored --nocapture
```

Host networking lets the selected daemon reach the disposable registry. The socket
selection is explicit; this command is not a fleet deployment command.

## Limits

No fleet deployment, GPU streaming acceptance, image rebuild or image-contract run
was performed. This slice changes image orchestration and launch preparation, not
image contents or the media pipeline. The standard devtools suite reports its usual
GPU/interpipe limitations; the separate runtime acceptance ran in the agent development
image. Podman/rootless certification, builds, updater redesign, and the remaining CLI
caller migrations are outside #231. No promotion to `develop` or `main` is included.
