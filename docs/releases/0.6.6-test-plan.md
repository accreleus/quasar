## #824 Release detection: verify the manifest signature when trusted keys are configured

**Changed:** on an owned install, detection asks the control plane's recovery actor to verify each new stable release's `.sig` over the fetched manifest (control socket `POST /v1/verify-manifest`); a refused or unanswered check keeps the release out of the list and counts it in the run's `manifest_errors`. Mode `off`, no actor, or an actor older than the route: unchanged.
**Rows:** on the lab control plane, running the integration image as an owned install (its machine runs `quasar-recovery`; without one detection checks nothing and these rows prove nothing). Detection skips only versions it already stored, so a deleted stable row is re-detected on the next "Check now". Judge each row by the detection run in Fleet ▸ Jobs, not by the Releases list (on an integration image every stable release is below the installed schema and held back anyway).
- Pick the row, once: in the control plane's database, `SELECT id, version FROM platform_releases r WHERE channel = 'stable' AND NOT EXISTS (SELECT 1 FROM platform_apply_runs a WHERE a.release_id = r.id) AND NOT EXISTS (SELECT 1 FROM platform_apply_attempts t WHERE t.release_id = r.id) ORDER BY built_at DESC LIMIT 1;` (a row an apply run used is `ON DELETE RESTRICT`). Keep its **version**: re-detection inserts it under a new id, so every delete below goes by version. Note the recorded trust values (`machine.json` `inputs.trust` on that machine) for the reset.
- (1) Default trust (`verify`, org key): `DELETE FROM platform_releases r WHERE channel = 'stable' AND version = '<version>' AND NOT EXISTS (SELECT 1 FROM platform_apply_runs a WHERE a.release_id = r.id) AND NOT EXISTS (SELECT 1 FROM platform_apply_attempts t WHERE t.release_id = r.id);` (it must report `DELETE 1`; anything else, stop), then "Check now". The run shows `releases_new: 1`, `manifest_invalid: 0`.
- (2) Wrong key: `docker exec -it quasar-recovery quasar-recovery reconfigure --yes "QUASAR_UPDATER_TRUSTED_KEYS=other:$(head -c32 /dev/urandom | base64)"`, delete the row again by version (same statement, `DELETE 1`), "Check now". The run shows `releases_new: 0`, `manifest_invalid: 1`, and `manifest_errors` naming the version and `signature refused by the recovery actor`; the control plane logs `platform release manifest rejected`, the actor `actor-manifest-refused`.
- (3) Off: `reconfigure --yes QUASAR_UPDATER_SIGNATURE_MODE=off`, "Check now" (row (2) left the version unstored, so no delete). The run shows `releases_new: 1`.
- Reset: `reconfigure` both variables back to the recorded values.
**Pass:** with keys configured, a release that does not verify is not listed and the refusal shows in the Jobs run summary and both logs; with the right key, and under `off`, it is listed as before.
**Hosts:** the lab control plane's machine (no GPU path involved).
- [x] Implemented (merged into integration/0.6.6)
- [ ] Tested on the lab
