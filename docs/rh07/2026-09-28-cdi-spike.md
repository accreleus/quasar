# RH-07 spike: NVIDIA through CDI with the driver volume, in every engine mode (#398)

Run on 2026-09-28 on the rootless lab machine: Fedora CoreOS 44 (uCore), SELinux enforcing,
read-only `/usr`, RTX 5090, driver 615.71.09 (open kernel module), NVIDIA Container Toolkit
1.20.1. The host's NVIDIA userspace is **CUDA-only** (`nvidia-driver-cuda`): no EGL, GLX, Vulkan
ICD, GBM or 32-bit libraries. Engines: Docker 29.7.2 rootful, Docker 29.8.1 rootless, Podman
5.8.4 rootless. Image: the RH-06 agent image. No product code was changed.

## Findings

**1. One request shape works on all three engines: `HostConfig.DeviceRequests =
[{"Driver":"cdi","DeviceIDs":["nvidia.com/gpu=all"]}]`.** Created through each engine's
Docker-compatible API, the container gets the device nodes, the spec's libraries (`libcuda`,
`libnvidia-encode`, …), `nvidia-smi` and the ldcache hook. Do **not** put a CDI name in
`HostConfig.Devices`: Podman's compatible API either stats it as a file (`stat
nvidia.com/gpu=all: no such file or directory`) or appends the cgroup permissions to it
(`unresolvable CDI devices nvidia.com/gpu=all::rwm`).

**2. What each engine reports back differs (this is #397's input).**

| engine | `HostConfig.DeviceRequests` | `HostConfig.Devices` | `HostConfig.Runtime` |
|---|---|---|---|
| Docker rootful / rootless | `[{"Driver":"cdi","Count":0,"DeviceIDs":["nvidia.com/gpu=all"],"Capabilities":null,"Options":null}]`, exactly as sent | `[]` | `runc` |
| Podman (compat inspect) | `null` | the **expanded** nodes: `/dev/nvidia{0,ctl,-modeset,-uvm,-uvm-tools}`, `/dev/dri/card1`, `/dev/dri/renderD128`, each with `CgroupPermissions: ""` | `oci` |

So on Podman the request cannot be read back as sent; the read-back must accept the expanded
NVIDIA and DRI nodes that a CDI request produces, with empty permissions, and nothing else.

**3. Capability facts.** Docker's `/info` lists `CDISpecDirs` when CDI is on (rootful
`[/etc/cdi /run/cdi]`; rootless adds the user's own dirs). Podman's compatible `/info` reports
`CDISpecDirs: null` although Podman always resolves CDI, so "CDI available" is decided from the
engine (`podman`) there, never from that field. Both engines report `name=rootless` in
`SecurityOptions` when rootless; Podman's `/version` names its component `Podman Engine`.

**4. SELinux: Podman needs `container_use_xserver_devices`.** NVIDIA's nodes are labelled
`xserver_misc_device_t`. With labels on, a Podman container (`container_t`) cannot open
`/dev/nvidiactl` (`Failed to initialize NVML: Insufficient Permissions`). Turning on the
policy's own boolean for exactly that label, `container_use_xserver_devices`, fixes it with
labels still on. That is narrower than `label=disable` or `container_use_devices`. Rootful
Docker worked with labels on and the boolean off; rootless Docker is not SELinux-confined on
this host. **Decision:** host preparation sets the boolean on NVIDIA hosts with SELinux
enforcing, and no GPU container uses `label=disable`.

**5. The driver volume is still needed on CUDA-only hosts, and coexists with CDI.** CDI supplies
the device nodes and the compute and encode libraries. The driver volume supplies GLX, EGL, the
Vulkan ICD, GBM and the 32-bit libraries. With both, in every mode:

- `vulkaninfo` reports `NVIDIA GeForce RTX 5090`, driver 615.71.09.
- `videotestsrc ! vulkanupload ! vulkanh264enc` and `… ! vulkanh265enc` (profile `main`) encode
  600 frames at 1080p60 successfully.

The libraries CDI injects and the volume's copies are the same version, because the volume is
provisioned for the loaded kernel module.

**6. Two things block the agent from provisioning the volume itself on a rootless engine today:**

- Self-identification fails on Podman ("could not determine this process's own container id").
  That is #405.
- The explicit host-path escape hatch validates through a diagnostic helper, which Podman
  refuses at read-back. That is #397.

For this spike, the volume was provisioned by the agent under rootful Docker and copied into the
rootless engines' volumes.

**7. Community findings (a rootless Podman attempt on the same driver branch):**

- The volume should exclude `nvidia_drv.so` and `libglxserver_nvidia.so.*`. These are X server
  modules; on the client library path their relocations break the driver's load chain. Our
  provisioned volume contains both.
- App containers should also set `VK_LOADER_DRIVERS_DISABLE=*lvp_icd*`.
- Podman's self-identification path is `…/overlay-containers/<id>/userdata/…`.

The same attempt could not initialise Vulkan inside the Steam app container on this driver.
That risk stays open until a live Steam session runs (#399).

**8. Not a CDI issue:** the agent's `media-probe` subcommand panics in the compositor ("Failed to
create GsGlesbuffer") identically in all three modes, rootful Docker included, when run ad hoc
outside the agent's own wiring. It is recorded for the live-session work, not attributed to CDI.

## Recipe for #399 (GPU injection)

- **Request:** every NVIDIA consumer (session containers, helpers, probes, the node agent)
  requests `DeviceRequests [{Driver:"cdi", DeviceIDs:["nvidia.com/gpu=all"]}]`.
- **Fallback:** `--gpus` (`{Count:-1, Capabilities:[["gpu"]]}`) only on rootful Docker whose
  `/info` reports no `CDISpecDirs`.
- **When CDI is unusable:** a host with no NVIDIA CDI device fails `runtime_cdi` (or
  `runtime_cdi_gpu<N>`), naming host preparation. There is no privileged fallback.
- **Driver volume:** keep it. Drop the X server modules from the volume, and add the
  `lvp_icd` disable to app containers.

## Recipe for host preparation (#400), per engine mode

| mode | CDI specification | SELinux | other |
|---|---|---|---|
| Docker rootful | `/etc/cdi` or the toolkit's `/var/run/cdi` spec | nothing extra observed | — |
| Docker rootless | same spec (seen through rootlesskit) | not confined here | lingering, the user's `docker.service` |
| Podman rootless | same spec | `container_use_xserver_devices=on` | lingering, `podman-restart.service`, `podman.socket` |

No `no-cgroups` change and no `nvidia-container-runtime` were needed: CDI does not use the legacy
runtime hook.

**Engine versions:** only the versions above were tested. They are the floor RH-07 claims until
another is run.
